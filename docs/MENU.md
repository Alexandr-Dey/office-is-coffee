# MENU — Love is Coffee v2.0

> **Источник истины для цен и позиций** — подтверждено владельцем 2026-04-22.
> Код в `src/lib/menu.ts` должен соответствовать этому документу.
> Нет в таблице — нет в меню. `—` = размера нет, не подставлять соседний.

Валюта: **тенге (₸)**. Формат: `1 200₸` (неразрывный пробел в тысячах). Никогда «тг», «KZT», «T», «тнг».

## Схема типа

```ts
type Size = 'S' | 'M' | 'L';
// Регистр заглавный — в коде и Firestore. Не менять, исторические заказы завязаны.

type CategoryId =
  | 'classic_coffee' | 'author_coffee' | 'ice_coffee'
  | 'home_tea' | 'author_tea' | 'matcha' | 'ice_tea'
  | 'smoothie' | 'fresh' | 'lemonade' | 'milkshake';

interface MenuItem {
  id: string;
  name: string;
  category: CategoryId;
  prices: Partial<Record<Size, number>>; // только реально доступные размеры
  addons: { milk: boolean; syrup: boolean; honey: boolean };
  isHot?: boolean;      // переопределяет COLD_CATEGORIES дефолт
  composition?: string;
  countsForLoyalty: boolean;
}
```

## Размеры

| Код | Объём |
|---|---|
| S | 250 мл |
| M | 350 мл |
| L | 450 мл |

- **S** — только у: Американо, Капучино, Флэт уайт, Эспрессо (S/M)
- **Только L** — у: Мокко, Лавандовый раф, все Айс ти, все Лимонады, все Молочные коктейли

## Добавки

| Тип | Цена |
|---|---|
| Сироп | +250₸ |
| Мёд | +250₸ |
| Альтернативное молоко (5 видов) | +500₸ |

Правила `addons` по категориям:

- `classic_coffee` Капучино/Латте/Флэт уайт → `{milk:true, syrup:true, honey:false}`
- `classic_coffee` Американо/Эспрессо → `{milk:false, syrup:false, honey:false}`
- `author_coffee` все → `{milk:false, syrup:false, honey:false}`
- `ice_coffee` по умолчанию → `{milk:true, syrup:true, honey:false}`
  - Айс американо → `{milk:false, syrup:true, honey:false}`
  - Эспрессо тоник → `{milk:false, syrup:false, honey:false}`
- `home_tea` все → `{milk:false, syrup:true, honey:true}`
- `author_tea` все → `{milk:false, syrup:false, honey:true}`
- `matcha`, `ice_tea`, `smoothie`, `fresh`, `lemonade`, `milkshake` → `{milk:false, syrup:false, honey:false}`

Сироп бесплатен в холодных напитках (`isColdItem(item) === true`).

## Правила горячий/холодный

`isColdItem(item)` — сначала смотрит `item.isHot` (override), потом сверяется с `COLD_CATEGORIES` = `{ice_coffee, ice_tea, lemonade, fresh, smoothie, milkshake}`.

Явные переопределения:
- **Горячий шоколад** (категория `ice_coffee`): `isHot: true`
- **Какао** (категория `ice_coffee`): `isHot: true`
- **Айс матча** (категория `matcha`): `isHot: false`

Integrity-проверки в `menu.ts` при импорте модуля — билд упадёт если эти инварианты нарушены.

## Частые ошибки (не допускать)

- НЕ «Бомба би» → **Бамбл би**
- НЕ «Бомба матча» → **Бамбл матча**
- Айс матча — в категории `matcha`, не в `ice_tea`
- «Смузи-тропикс» не существует
- Смузи «Яблоко-грейпфрут» не существует (только во фрешах)

## Legacy-категории (normalize-on-read)

Исторические заказы в Firestore могут содержать старые ID категорий. Хелпер `normalizeCategoryId(raw)` в `src/lib/menu.ts` маппит их на актуальные и логирует в Sentry (`level: "info"`, `tag: "legacy_category_format"`).

| Старый ID | Новый ID |
|---|---|
| `coffee_classic` | `classic_coffee` |
| `coffee_author` | `author_coffee` |
| `tea_home` | `home_tea` |
| `tea_author` | `author_tea` |

Когда в Sentry прекратятся события с `legacy_category_format` — хелпер и легаси-ветку в `functions/index.js:coffeeCategories` можно удалить.

## Расширения схемы (backlog, не реализовано)

Семантика полей продумана и отражена в бывшем `MENU-DATA.md`. При будущей реализации — соблюдать её. Сейчас в `MenuItem` этих полей **нет**.

### `tags: Array<'hit' | 'new' | 'season'>`

Фасетная навигация / фильтры в PWA, badge «Хит» / «Новинка» / «Сезонное» на карточках.

- `hit` — хит продаж (владелец отмечает вручную)
- `new` — новая позиция
- `season` — сезонная, связана с `activeFrom`/`activeTo`

### `radarData: { acidity, sweetness, bitterness, body, aroma: 1..5 }`

Вкусовой профиль для радар-визуализации на детальной странице напитка (`/menu/[id]`). Ось — 1..5. Полно заполнять только когда будет редактор в админке или ручной контент-пак от владельца.

### `sortOrder: number`

Ручной порядок позиций внутри категории. Сейчас порядок фиксирован физическим порядком массива `MENU_ITEMS` в `menu.ts` — для перестановки нужно править код. `sortOrder` даст owner-level контроль из админки после миграции на Firestore.

### `activeFrom: string | null`, `activeTo: string | null` (формат `MM-DD`)

Сезонная активация. Позиция показывается клиенту только если текущая дата UTC+5 попадает в окно. Связано с TODO «Сезонная ротация hero» — см. `docs/TODO.md`.

Пример:
```json
{
  "id": "mulled_wine",
  "tags": ["season"],
  "activeFrom": "11-01",
  "activeTo": "03-31"
}
```
